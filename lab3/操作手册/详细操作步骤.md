# 实验三 详细操作步骤

本手册记录本组在华为云四台服务器上完成实验三的实际步骤，命令均可在对应服务器上直接执行。

## 1 服务器分工

| 节点（主机名） | 内网 IP | 本地 SSH 别名 | 作业角色 | 部署内容 |
| --- | --- | --- | --- | --- |
| compiler | 172.31.4.138 | `huawei-compiler` | 服务器 A：编译、压测 | JDK 21、Maven 3.9.16、JMeter 5.6.3 |
| course-node2 | 172.31.8.71 | `huawei-node1` | 服务器 B：应用 | productdemoaop 容器 |
| course-node1 | 172.31.6.17 | `huawei-mysql` | 服务器 C：数据库 | MySQL 9.2.0 容器 |
| manager | 172.31.13.176 | `huawei-manage` | 服务器 D：监控 | Swarm 管理节点、Prometheus 3.7.3 |

四台均为 Ubuntu 18.04.6、2 核、约 1.8 GiB 可用内存，组成一个 Docker Swarm 集群（manager 为 Leader），每个节点运行 node-exporter。

## 2 编译与打包

```bash
cd /root/spring-fundamentals/clonefactory
mvn install -Dmaven.test.skip=true
cd "/root/spring-fundamentals/4. SpringAOP"
mvn install -pl core -am -Dmaven.test.skip=true -U -e -B
mvn clean pre-integration-test -pl productdemoaop -Dmaven.test.skip=true
```

生成镜像 `swr.cn-north-4.myhuaweicloud.com/ooad-mytx/productdemoaop:0.0.1-SNAPSHOT`。

## 3 部署（manager 上执行）

```bash
cd "/root/spring-fundamentals/4. SpringAOP/conf/docker"
docker stack deploy -c productdemoaop-docker.yml --with-registry-auth lab
docker service ls
```

应用通过节点标签 `app==yes` 固定在 course-node2，MySQL 固定在 course-node1，Prometheus 运行在 manager。
应用启动参数：Tomcat 最大线程 300，Druid 连接池最大 300、最小空闲 100、初始 100。

## 4 Prometheus 配置

`/root/prometheus/prometheus.yml` 中 node 任务的 targets 改为四台服务器的内网 IP：

```yaml
- job_name: 'node'
  static_configs:
    - targets: ['172.31.6.17:9100', '172.31.8.71:9100', '172.31.13.176:9100', '172.31.4.138:9100']
```

打开 `http://<manager公网IP>:9090`：
- Status → Target health：node 4/4、productdemoaop 1/1、prometheus 1/1 均为 UP；
- Status → Rule health：13 条记录规则状态均为 OK；
- Query 中查询 `spring:jvm_threads_live_threads`、`node:cpu_usage_percent`、`node:memory_usage_percent`。

## 5 JMeter 准备（compiler 上执行）

```bash
unzip apache-jmeter-5.6.3.zip -d /root
echo 'export PATH=/root/apache-jmeter-5.6.3/bin:$PATH' >> ~/.profile
# 报告采样间隔改为 1 秒
grep overall_granularity /root/apache-jmeter-5.6.3/bin/user.properties
# jmeter.reportgenerator.overall_granularity=1000
```

`ReadProduct.jmx` 与 `WriteProduct.jmx` 中的 hostname 改为应用服务器内网 IP `172.31.8.71`，port 为 `8080`。

`jmeter-command.sh` 中 JMeter 堆设为 `-Xms256m -Xmx512m -Xss256k`。指导书给出的 `-Xms2g -Xmx4g` 在 1.8 GiB 内存的主机上无法启动（JVM 报 “insufficient memory … failed to map 2147483648 bytes”，见压测目录中的 hs_err 日志），因此按实际内存调小。

## 6 执行测试

在 `/root/lab3-run`（复制自 `4. SpringAOP/jmeter` 的 jmx、csv 与 jmeter-command.sh）中依次执行，每组之间间隔 30 秒：

```bash
# 读取：每线程 2 次循环
for t in 1000 1050 1100 1150 1200; do bash jmeter-command.sh ReadProduct $t 10 2; sleep 30; done
# 写入：每线程 1 次循环
for t in 1000 1100 1200 1300; do bash jmeter-command.sh WriteProduct $t 10 1; sleep 30; done
```

每组生成 `<计划>-<线程>-10-<循环>.jtl` 原始数据和同名 HTML 报告目录，并记录每组的开始和结束时间。

### 6.1 吞吐上限测试

在 `/root/lab3-run/sat` 中，让每个线程收到响应后立即发送下一个请求，吞吐量即由系统处理能力决定：

```bash
# 写入：每组 10000 次请求
for t in 20 50 100 200; do bash jmeter-command.sh WriteProduct $t 5 $((10000 / t)); sleep 30; done
# 读取：每组 30000 次请求（10000 次时稳态不足 2 秒，故加大）
for t in 20 50 100 200; do bash jmeter-command.sh ReadProduct $t 5 $((30000 / t)); sleep 30; done
```

稳态吞吐量取升压结束到最后 1 秒之前完成的请求数除以该时长。

## 7 导出监控数据

测试结束后，按每组首个请求前 15 秒到最后一个响应后 30 秒的窗口，以 2 秒步长调用 Prometheus `query_range` 接口，导出三项查询，每组一个 JSON 文件。
